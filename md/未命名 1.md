## 第1章 绪论
### 1.1 选题的背景
　　生产管理是制造业运营的核心环节，直接影响企业的效率、成本和产品质量。近些年，越来越多的制造企业开始用信息化平台替代传统的人工调度方式，MES（Manufacturing Execution System，制造执行系统）的应用也越来越普遍[1][2]。在这个过程中，工单管理逐渐被认为是推动精益生产、缩短交付周期的关键抓手[3]，围绕特定行业构建专业化的生产管理系统也成了制造业信息化的一个重要方向。

　　玻璃是建筑、汽车、电子、光伏等行业的基础材料，市场需求一直在增长。玻璃生产本身有一些比较特殊的地方，比如高温连续作业、原料配比精度要求高、产品规格多样，生产过程涵盖配料、熔化、成型、退火、切割、深加工等多道工序，每道工序都涉及大量物料的领用和消耗[4][5]。石英砂、纯碱这些原料容易受潮结块，玻璃原片易碎且规格繁多，成品还要按厚度、尺寸、透光等级等参数做精细分类。这些行业特性对生产管理的精细化程度和物料保障的响应速度提出了很高的要求。

　　从政策层面看，"中国制造2025"和"工业互联网"政策推动下，制造业数字化转型已经是大势所趋[6]。但现实情况是，大量中小型玻璃企业还在用人工台账、Excel和纸质单据来管理生产，计划与物料脱节、进度跟踪缺失、库存数据滞后、批次追溯困难这些问题一直没有得到很好的解决[7]。市面上的通用ERP系统虽然能覆盖一些基础功能，但在生产排产、领料出库、完工入库、质量追溯这些环节的衔接上还是不够紧密，和玻璃行业的实际需求之间存在明显的差距[8]。因此，设计一套面向玻璃生产企业的一体化生产管理系统，对于推动行业信息化升级有着比较现实的意义。

### 1.2 选题目的和意义
　　本研究的目的是设计并实现一套基于Spring Boot的玻璃生产管理系统，把生产排产、物料管理、领料出库、完工入库、库存管理、调拨和统计分析这些功能整合到一个平台上，解决当前玻璃企业普遍面临的信息孤岛和流程割裂问题。

　　从现实需求来说，现代玻璃企业的生产工艺已经比较先进了，自动化配料、连续熔化、精准退火这些都不稀奇[5]。但管理手段跟不上。完成一次生产任务要经历"客户订单→计划排产→原料领用→生产执行→质量检验→完工入库→成品交付"这么多环节，计划员和仓管员得在ERP、Excel、纸质单据之间来回切换，出错在所难免。订单分配环节如果没有系统支撑，信息传递的效率和准确性都很成问题[9]。所以需要一套系统化的方案，把这些分散的流程归拢到一起。

　　理论层面上，本研究把前后端分离架构和生产管理的业务需求结合起来，探索Spring Boot + Vue.js在制造业场景中的应用，同时兼顾了架构安全性方面的考量[10]。具体来说，系统提出了三个核心机制：基于生产工单驱动的全流程管理、基于物料标签与二维码的全流程追溯[11]、基于BOM自动展开的领料清单生成，并且引入了安全库存阈值驱动的库存预警[12]。实践层面上，系统以工单为主线串联了订单、排产、领料、质检、入库、盘点、调拨等业务，通过标签和批次实现质量追溯，通过预警和统计辅助决策。整套系统采用低成本、易部署的架构，适合中小型玻璃企业使用。

### 1.3 国内外研究现状

　　国外方面，制造系统的柔性化和模块化设计一直是研究热点，核心思路是让架构足够灵活以适应产品切换和市场波动[13]。在生产与仓储的协同上，SAP S/4HANA等大型ERP平台已经能做到生产计划、仓储管理、实验室信息管理之间的紧密集成，但实施成本和定制周期对中小企业来说门槛太高[14]。云制造和AI调度这几年进展也不少，为中小企业获取先进管理能力打开了新路径，不过数据安全和落地成本还是绕不开的问题[15]。总体来看，国外的研究在系统架构和智能化方面走得比较靠前，但方案普遍偏重、偏贵，对特定行业的深度适配做得不多。

　　国内这边，围绕生产管理系统的研究覆盖面比较广。系统架构层面，针对地铁车辆架大修、离散制造等场景已经有了一些实践成果，但大多聚焦于特定场景，通用性有限[1][10]。工单管理驱动精益生产的思路也得到了实证支持，不过已有研究偏重管理机制分析，技术实现层面讲得不多[3]。订单到生产计划的自动分配有人做过，但工单级别的细粒度管控还是空白[9]。质量追溯方面，二维码追溯和全生命周期追溯在供水、食品、工业品等领域都有了应用[7][11]，只是和生产工单、质检任务的集成度普遍不高。物料需求计划方面，MRP系统能根据订单算出需求，但货位分布和智能推荐考虑得还不够[4]。仓储管理这块，低代码开发降低了成本，库存预警也有了实践[8][12]，但生产领料和完工入库的业务联动、预警和排产决策的打通都还不到位。商业软件方面，用友U8、金蝶K/3二次开发成本高，黑湖智造、简道云在深度定制上还差点意思。

　　总的来看，现有方案在玻璃行业适配、订单到交付的业务闭环、中小企业实施门槛、生产与仓储联动这几个方面都还有明显不足。本研究正是针对这些问题，尝试做一套面向玻璃生产企业的、功能完整且门槛低的生产管理系统。

### 1.4 本文开发内容

　　本文基于Vue.js + Spring Boot的前后端分离架构，设计并实现一套面向玻璃生产企业的生产管理系统。系统采用RBAC权限模型做功能隔离，业务上覆盖基础数据管理（物料、BOM、工艺路线、设备工位、质量标准、仓库货位、供应商与客户）、客户订单与生产计划管理、生产工单全生命周期管理、质量管理、仓储与库存管理、调拨管理和统计分析等模块。

　　在生产流程上，系统围绕"订单→计划→工单"的三级驱动机制展开：客户订单可一键生成生产计划，计划自动生成工单，工单开工时根据BOM递归展开生成领料出库单，报工完工时自动生成成品入库单并更新库存。质量管理方面，入库单会自动触发质检任务，质检结果系统判定，不合格品支持返工、报废、让步接收，同时基于物料批次和标签实现全流程追溯。仓储方面，支持多类型出入库、扫码作业、货位推荐、库存盘点、跨仓调拨和安全库存预警。此外还提供出入库统计和库存流水统计等报表功能。后台管理包括用户、角色、权限、字典、操作日志等基础功能。

### 1.5 本章小结

　　本章介绍了玻璃生产企业在生产管理环节面临的信息化困境，说明了开发一套行业适配的生产管理系统的现实意义。在研究现状部分，分别从国外和国内两个维度梳理了生产管理系统、工单管理、质量追溯、仓储库存等方向的已有成果，指出了现有方案在行业适配性、业务闭环、实施成本和生产仓储联动等方面的不足。在此基础上，明确了本文的开发内容，包括基础数据管理、订单与计划管理、工单全流程管理、质量检验与追溯、仓储库存管理、调拨和统计分析等功能模块。以上内容为后续章节的需求分析、系统设计和功能实现提供了依据。

## 第2章 系统需求分析

### 2.1 系统功能需求分析
本系统主要解决玻璃生产企业在排产调度和物料保障方面的管理问题，覆盖从生产计划下达到成品完工入库的主要业务环节。根据实际业务流程和数据库表的设计情况，系统功能划分为以下几个部分：基础数据管理、入库业务、入库退货、生产工单管理、出库业务、出库退货、库存调拨、物料标签管理与扫码作业、库存信息与库存流水查询、系统权限控制与操作审计、统计监控。

| 功能编号 | 功能名称 | 功能说明 |
|---|---|---|
| 1-1 | 物料信息管理 | 管理石英砂、纯碱、石灰石等原料及平板玻璃、特种玻璃等成品的物料档案，记录编码、规格、成分、安全库存等信息，支持物料分类与BOM管理 |
| 1-2 | 工艺路线管理 | 维护玻璃生产各环节（熔制、成型、退火、切割等）的工艺路线，管理工序步骤与工艺参数（温度区间、成型速度、退火曲线等），支持版本控制 |
| 1-3 | 设备与工位管理 | 维护窑炉、成型机、切裁机等设备的基本参数、产能数据与维护记录，划分生产工位并关联设备与操作人员，支持设备状态实时更新与维护周期管理 |
| 1-4 | 质量标准管理 | 制定原料成分偏差范围、成品平整度公差、透光率指标等检验标准，配置检验项目与合格判定规则，按物料类型关联对应标准 |
| 1-5 | 仓库与货位管理 | 维护仓库基本信息与货位编号，支持按物料组配置推荐仓库，实现货位状态实时更新 |
| 1-6 | 供应商与客户管理 | 维护供应商资质信息与供货质量评级，管理客户基本信息与合作状态，供采购和销售业务使用 |
| 2-1 | 客户订单管理 | 接收客户订单，记录产品类型、规格、数量、交付日期等信息，支持订单审核与状态跟踪，可一键生成生产计划 |
| 2-2 | 生产计划管理 | 根据客户订单与产能情况制定月度、周度生产计划，明确各批次玻璃的计划数量、开工时间与完工时间，BOM展开校验原料库存充足性，自动生成生产工单 |
| 2-3 | 生产工单管理 | 管理工单从创建到关闭的完整过程，支持排产调度（计划时间、优先级、车间分配），状态流转（待排产→生产中→已完工→已关闭），开工时自动递归展开BOM并生成领料出库单。报工完工时记录实际完成数量，自动生成成品入库单并更新库存 |
| 2-4 | 交付管理 | 管理客户订单的交付执行，创建交付记录并关联客户订单与出库单，记录交付数量、交付时间、物流信息，支持交付进度跟踪与回写订单完成状态 |
| 2-5 | 质检与不合格品管理 | 根据入库单自动生成质检任务并分配至质检员，录入检验数据后系统自动判定合格与否。对不合格品记录缺陷类型与严重程度，支持返工、报废、让步接收等处理方式 |
| 2-6 | 质量追溯 | 基于物料批次与标签信息，支持正向追溯（从原料到成品）与反向追溯（从成品到原料），关联入库记录、生产工单、质检结果，串联起完整的质量追踪链条 |
| 3-1 | 入库单管理 | 支持采购入库、生产入库、调拨入库等多种入库类型，记录入库时间、仓库、货位、数量及供应商信息，扫码确认后自动更新库存并记录流水 |
| 3-2 | 出库单管理 | 支持生产领料、销售出库、调拨出库等多种出库类型，根据物料组自动推荐仓库与货位，扫码确认后自动扣减库存并记录流水 |
| 3-3 | 入库退货管理 | 支持已入库物料退货操作，记录退货原因、退货数量、退货时间等信息 |
| 3-4 | 出库退货管理 | 支持已出库物料退货操作，记录退货原因、退货数量、退货时间等信息 |
| 3-5 | 物料标签管理 | 入库完成后自动生成物料标签，记录标签编号、物料批次、数量、货位等信息，支持标签打印与二维码扫码，作为出入库扫码和质量追溯的数据依据 |
| 4-1 | 库存信息管理 | 查询物料库存数量与分布情况，支持按仓库、货位、物料、批次等条件查询与汇总。设置库存安全阈值，低于阈值时自动触发预警通知 |
| 4-2 | 库存盘点管理 | 支持全盘、循环盘、抽盘等盘点方式，自动快照系统库存，录入实盘数量后计算差异，支持盘点调整自动修正库存 |
| 5-1 | 调拨单管理 | 支持物料跨仓库调拨，创建调拨单后自动生成调拨出库单与调拨入库单，完成出库与入库后自动回写调拨进度 |
| 6-1 | 入库统计 | 按时间段、供应商、仓库、物料等维度统计入库情况，生成入库统计报表 |
| 6-2 | 出库统计 | 按时间段、车间、仓库、物料等维度统计出库情况，生成出库统计报表 |
| 6-3 | 库存流水统计 | 记录库存变动明细，支持按物料、仓库、时间段、流水类型等维度查询与导出 |

#### 2.3.2 核心业务用例模型
图2-2为业务员用例图，把生产主管、质检员、仓管员三个业务角色的操作用例进一步拆细。生产主管的用例包括客户订单管理、生产计划管理、生产工单管理（含排产、开工、报工、完工）和交付管理，基本贯穿了从接单到交货的全过程。质检员对接的用例是质检与不合格品管理和质量追溯，前者负责录入检验结果、判定合格与否以及处理不合格品（返工、报废或让步接收），后者用于正向或反向追溯质量链条。仓管员这边涉及的用例比较多：入库确认、出库确认、库存查询、库存盘点、调拨管理，另外还有物料标签管理，入库完成后自动生成的标签由仓管员打印和维护，同时也是扫码出入库与质量追溯的数据载体。

在用例之间还存在三处自动联动。一是工单开工会自动挂接领料出库，背后的逻辑是BOM递归展开，系统据此生成一张领料出库单，把物料需求直接推到仓管员面前。二是报工完工即触发入库，系统自动写一张成品入库单，省去仓管员手工建单的步骤。三是采购入库单确认后会顺带拉起一条质检任务，质检与不合格品管理由此被纳入入库确认的后续动作。这三处联动在用例图中以自动勾连的方式标注，把生产执行和仓储质检两条线拴在了一起。

　　数据流图（Data Flow Diagram，DFD）从数据流转的角度刻画系统内部的加工逻辑，能够比较直观地呈现数据在各处理过程和数据存储之间的走向。本节按业务模块分成四张DFD来画，分别覆盖基础数据管理、生产计划与工单管理、生产执行与质量管理、仓储与库存管理。

#### 2.4.1 基础数据管理模块数据流图

　　基础数据模块的数据流图（图2-4）相对简单，管理员是唯一的数据发起方。管理员在界面上做增删改查，数据分头流向六个处理过程：物料信息管理（P1）、仓库货位管理（P2）、工艺路线管理（P3）、设备工位管理（P4）、质量标准管理（P5）和合作方管理（P6）。每个处理过程背后各挂一张数据存储，P1对接物料表/BOM表（D1），P2对接仓库表/货位表（D2），P3对接工艺路线/工序表（D3），P4对接设备表/工位表（D4），P5对接检验标准表（D5），P6对接供应商/客户表（D6），读写均为双向。这些基础数据一旦维护到位，上层的生产、质量和仓储模块才有据可依。

（此处对应：图2-4 基础数据管理模块数据流图）

#### 2.4.2 生产计划与工单管理模块数据流图

　　这张DFD（图2-5）要解决的核心问题是：如何把一张客户订单逐级拆解为可执行的生产工单，并在交付后把状态回写回来。数据流主线被设计为"订单→计划→工单→交付"的层层递推。生产主管录入订单后，P1（客户订单管理）先把数据落到客户订单表（D1），随后通过"一键生成计划"动作把任务传导至P2（生产计划管理），P2生成计划并存入D2。P2再往下推，自动生成工单功能把计划数据递交给P3（生产工单管理），P3写入生产工单表（D3），到这一步生产主管就可以排产、开工、报工了。交付阶段由P4（交付管理）接手，生产主管创建交付记录、客户参与签收，数据写入交付记录表（D4）。值得留意的是，P4还会把完成状态回写到D1，订单从创建到交付，数据在这条链路上走了一个完整的回路。

（此处对应：图2-5 生产计划与工单管理模块数据流图）

#### 2.4.3 生产执行与质量管理模块数据流图

　　工单一旦开工，数据流就从"计划"切换到了"执行"。图2-6描述的正是这个阶段：生产主管扫码领料，数据流向P1（领料出库扫码），P1与出库单表（D1）双向交互，完成物料发放并刷新出库单状态。生产收尾后进入报工环节，报工数据流入P2（报工完工），P2往入库单表（D2）写入一条成品入库单。紧跟着，P2把质检需求递给P3（质检与不合格品），质检员在这里录入实测值，系统自动比对上下限做出判定，结果连同不合格品处理记录一并落入质检/不合格品表（D3）。另外一条支线是质量追溯（P4），质检员可以随时发起追溯查询，P4从追溯记录（D4）中检索关联数据，把原料批次、生产工单和质检记录串成一条可回溯的链路返回给查询者。

（此处对应：图2-6 生产执行与质量管理模块数据流图）

#### 2.4.4 仓储与库存管理模块数据流图

　　仓储模块（图2-7）的数据流比前面几张都密，虽然外部实体只有仓管员一个，但处理过程有五个、数据存储也有五张表。日常出入库走的是P1（入库确认）和P2（出库确认）：扫码入库时P1读写入库单表（D1），同时往库存信息/流水表（D3）写入增加记录。扫码出库时P2读写出库单表（D2），同时往D3写入扣减记录。盘点由P4（库存盘点）负责，仓管员录入实盘数量后，P4与盘点单表（D4）双向交互，并对D3做快照和差异调整。调拨则是P5（调拨管理）的活，仓管员发起调拨申请后P5与调拨单表（D5）交互，再分别向P1和P2各推一张调拨入库单和调拨出库单，完成物料的跨仓搬运。库存管理（P3）从D3读取汇总数据，给仓管员提供多维度查询和安全库存预警。

（此处对应：图2-7 仓储与库存管理模块数据流图）
