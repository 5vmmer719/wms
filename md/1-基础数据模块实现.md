# 5.1 基础数据模块实现（物料、分类、BOM、仓库货位）

## 5.1.1 流程图

管理员登录系统后进入基础数据管理模块，首先选择需要管理的数据类型（物料、分类、BOM、仓库或货位），系统加载对应的数据列表。当执行新增操作时，管理员填写完整的基础数据信息，系统进行前端表单验证，验证通过后提交至后端。后端接收请求后执行权限校验，校验通过则进行数据完整性验证，验证成功后将数据插入数据库，修改数据状态为已添加，最后返回操作结果。若验证失败，则提示错误信息，管理员需重新填写数据。对于修改操作，系统首先查询原有数据并回显至表单，管理员修改后提交，系统更新数据库记录。对于删除操作，系统先检查是否存在关联数据，若存在则禁止删除并提示，若不存在则执行删除操作。流程结束后，系统刷新数据列表显示最新结果。

```plantuml
@startuml
title 基础数据管理业务流程

start
:管理员登录系统;
:进入基础数据管理模块;
:选择数据类型;

if (操作类型?) then (新增)
  :填写基础数据信息;
  :前端表单验证;
  if (验证通过?) then (是)
    :提交至后端;
    :权限校验;
    :数据完整性验证;
    if (验证成功?) then (是)
      :插入数据库;
      :修改状态为已添加;
      :返回成功响应;
      :刷新数据列表;
    else (否)
      :返回错误信息;
      :重新填写数据;
    endif
  else (否)
    :显示错误提示;
    :返回表单页面;
  endif
elseif (修改) then
  :查询原有数据;
  :回显至表单;
  :修改数据信息;
  :提交更新请求;
  :更新数据库记录;
  :返回成功响应;
  :刷新数据列表;
elseif (删除) then
  :选择待删除记录;
  :检查关联数据;
  if (存在关联?) then (是)
    :禁止删除;
    :提示关联信息;
    stop
  else (否)
    :执行删除操作;
    :删除数据库记录;
    :返回成功响应;
    :刷新数据列表;
  endif
else (查询)
  :输入查询条件;
  :执行查询操作;
  :返回数据列表;
  :分页显示结果;
endif

:操作完成;
stop

@enduml
```

## 5.1.2 顺序图

```plantuml
@startuml
title 物料信息新增顺序图

actor 管理员
participant "前端页面" as Frontend
participant "MatController" as Controller
participant "MatServiceImpl" as Service
participant "MatMapper" as Mapper
database "MySQL数据库" as DB

管理员 -> Frontend: 点击新增物料按钮
Frontend -> Frontend: 弹出表单对话框
管理员 -> Frontend: 填写物料信息
Frontend -> Frontend: 执行表单验证

Frontend -> Controller: POST /base/mat/add
Controller -> Controller: @PreAuthorize权限校验
Controller -> Controller: 设置创建人信息

Controller -> Service: insertBaseMat(baseMat)
Service -> Service: 设置创建时间
Service -> Service: 数据完整性验证

Service -> Mapper: insertBaseMat(baseMat)
Mapper -> DB: INSERT INTO base_mat
DB --> Mapper: 返回影响行数
Mapper --> Service: 返回插入结果

Service --> Controller: 返回操作结果
Controller -> Controller: 封装响应对象
Controller --> Frontend: 返回成功响应

Frontend -> Frontend: 关闭表单对话框
Frontend -> Frontend: 刷新物料列表
Frontend --> 管理员: 显示操作成功提示

@enduml
```

管理员点击新增物料按钮，前端页面弹出表单对话框。管理员填写物料编码、名称、规格型号、单位、分类、安全库存等信息后，前端执行表单验证。验证通过后，前端向MatController发送POST请求，携带物料信息数据。Controller首先执行权限校验，确认用户具有物料新增权限，然后设置创建人信息为当前登录用户。随后Controller调用MatServiceImpl的insertBaseMat方法，Service层设置创建时间并进行数据完整性验证，验证通过后调用MatMapper的insertBaseMat方法。Mapper层执行SQL插入操作，将物料数据写入MySQL数据库的base_mat表，数据库返回影响行数。Mapper将结果返回给Service，Service返回给Controller，Controller封装成统一的响应对象返回给前端。前端接收到成功响应后，关闭表单对话框，刷新物料列表，并向管理员显示操作成功提示。

## 5.1.3 数据流图

```plantuml
@startuml
title 基础数据管理数据流图 (DFD)

skinparam rectangle {
  BackgroundColor<<external>> #E8F5E9
  BackgroundColor<<process>> #E3F2FD
  BackgroundColor<<storage>> #FFF3E0
  BorderColor #666666
  FontSize 12
}

' 外部实体
rectangle "管理员" as Admin <<external>>
rectangle "前端页面\n(Vue.js)" as Frontend <<external>>

' 数据处理过程
rectangle "P1\n权限校验处理\n(Controller层)" as P1 <<process>>
rectangle "P2\n数据验证处理\n(Service层)" as P2 <<process>>
rectangle "P3\n业务逻辑处理\n(Service层)" as P3 <<process>>
rectangle "P4\n数据持久化处理\n(Mapper层)" as P4 <<process>>

' 数据存储
rectangle "D1\nbase_mat\n(物料主数据)" as D1 <<storage>>
rectangle "D2\nbase_warehouse\n(仓库信息)" as D2 <<storage>>
rectangle "D3\nbase_location\n(货位信息)" as D3 <<storage>>
rectangle "D4\nbase_mat_bom\n(物料BOM)" as D4 <<storage>>
rectangle "D5\nsys_oper_log\n(操作日志)" as D5 <<storage>>

' 数据流
Admin --> Frontend : 请求数据
Frontend --> P1 : HTTP请求

P1 --> P2 : 认证通过请求
P1 --> Frontend : 权限拒绝响应

P2 --> P3 : 验证通过数据
P2 --> Frontend : 验证失败响应

P3 --> P4 : 业务处理数据
P3 --> D5 : 操作日志数据
P3 --> Frontend : 业务异常响应

P4 --> D1 : 物料数据操作
P4 --> D2 : 仓库数据操作
P4 --> D3 : 货位数据操作
P4 --> D4 : BOM数据操作

D1 --> P4 : 物料查询结果
D2 --> P4 : 仓库查询结果
D3 --> P4 : 货位查询结果
D4 --> P4 : BOM查询结果

P4 --> P3 : 持久化结果
P3 --> P2 : 处理结果
P2 --> P1 : 处理结果
P1 --> Frontend : HTTP响应
Frontend --> Admin : 界面展示

note right of P1
  @PreAuthorize权限校验
  @ss.hasPermi()验证
end note

note right of P2
  BeanValidator验证
  数据唯一性校验
end note

note right of P3
  设置审计字段
  业务规则处理
  @Transactional事务管理
end note

note right of P4
  MyBatis映射执行
  软删除处理(del_flag=1)
end note

@enduml
```

管理员通过前端页面发起数据操作请求，请求数据流入P1权限校验处理过程，P1通过@PreAuthorize注解验证用户权限，权限校验通过后将请求数据传递至P2数据验证处理过程。P2执行BeanValidator后端验证，检查数据完整性和唯一性，验证通过后将实体对象传递至P3业务逻辑处理过程。P3设置审计字段（createBy、createTime等），处理业务规则，记录操作日志至sys_oper_log表，使用@Transactional管理事务，将数据传递至P4数据持久化处理过程。P4通过MyBatis Mapper执行SQL操作，将数据写入base_mat、base_warehouse、base_location、base_mat_bom等数据存储，对于删除操作设置del_flag=1实现软删除。查询操作时，数据从数据存储逐层返回至前端展示；新增和修改操作时，数据从前端逐层传递至数据存储持久化。整个数据流清晰地展示了基础数据管理模块从权限校验、数据验证、业务处理到数据持久化的完整流转过程，体现了分层架构的设计原则，各层职责明确，数据流向清晰。
